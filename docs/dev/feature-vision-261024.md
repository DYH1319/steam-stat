# Steam Stat 最终形态功能清单

> 来源：2026-10-24 多轮需求访谈（功能篇）。UI 篇见 [ui-vision-261024.md](ui-vision-261024.md)。

**一句话定位：** Steam 数据档案馆。把 Steam 自己丢弃的数据（会话、好友动态、成就时间线、存档、截图、资料变化）永久存在本机，面向重度玩家和数据/统计爱好者。

**平台与边界：** Windows 加 Linux / Steam Deck，Linux 和 Deck 桌面模式做到功能可用，不做专门 UI。只做 Steam。数据永久保留。

**标记说明：** `[已有]` 现有功能，保持。`[改进]` 现有功能需要升级。`[新增]` 新功能。`[暂缓]` 评估后推迟。`[舍弃]` 评估后决定不做。每个模块末尾标优先级：P1 最高，P4 最低。

**落地进度（2026-11-04 盘点）：** 除标为 `[暂缓]` 和 `[舍弃]` 的条目外，本篇功能已全部实现。UI 篇的剩余待办见 [ui-vision-261024.md](ui-vision-261024.md) 末尾。

## 一、游玩会话记录（核心资产）｜P1-A

**1. 会话采集**
- `[已有]` 定时检测运行中的 Steam 应用，记录应用、账号、开始/结束时间和时长。
- `[已有]` 可开关自动检测，检测间隔 1~60 秒可调。
- `[已有]` 退出时如果有应用在运行，可选「以当前时间结束」或「作废」。
- `[改进]` 异常退出、断电、蓝屏、进程被强杀时，用最后一次心跳时间自动补全结束时间。
- `[改进]` 电脑睡眠/休眠的时段不计入时长（监听系统电源事件，切分或扣除）。
- `[新增]` 挂机/AFK 检测：键鼠无操作超过 N 分钟标为挂机，统计时区分「有效游玩」和「挂机」。
- `[新增]` 前台/后台时长：记录游戏窗口在前台的时间。
- `[新增]` 记录自己的 Rich Presence 变化（地图、模式、关卡等，需要 CM 登录），挂在对应会话下。
- `[新增]` 设备标识：每条会话记录来自哪台电脑或 Deck，为多设备同步做准备。

**2. 会话管理**
- `[新增]` 会话明细列表：可搜索、筛选、分页的原始会话表格。
- `[新增]` 手动编辑、删除、合并会话（修正挂了一夜、合并断开的短会话）。
- `[新增]` 会话备注和标签，形成游戏日记（和谁一起玩、打到哪里）。
- `[新增]` 自动清洗规则：忽略短于 N 秒的会话，自动合并间隔很短的会话，排除指定应用（如 Wallpaper Engine、SteamVR）。

**3. 历史导入与对账**
- `[新增]` 导入 Steam 累计时长作为基线（来自 localconfig.vdf 或 CM），安装本软件之前的历史也能体现。
- `[新增]` 定期快照 Steam 官方累计时长，和本地会话对账，发现在其他设备上的游玩。
- `[新增]` 从其他统计工具或 CSV 导入会话数据。

- `[新增]` 存档备份：定位存档目录，定期快照，保留版本历史。**只读，绝不写回**。
- `[新增]` 插件化存档解析：先在仓库内置少量解析器，再开放 WASM 沙箱插件给社区贡献。解析器只产出结构化数据，由统一的渲染器展示。
  - 2026-11-03 定稿：存档解析是**按游戏**的分析插件。插件读取原始存档（只读），产出该游戏的详细报告，例如以撒的通关标记、怪物图鉴、道具图鉴。

    - 插件放在独立公开仓库 `steam-stat-plugins`，应用内安装和更新，校验 SHA-256。首个插件为以撒的结合：重生（Rebirth ~ Repentance+）。
    - 存档备份中不再提供通用文件解析。
- `[新增]` 截图档案：索引 Steam 截图目录，按游戏和日期浏览，关联到当时的会话。
- `[新增]` 自己的资料变化：昵称、头像、等级、徽章的历史。

## 十、数据导出、备份与同步｜P3

- `[已有]` SQLite 本地存储；数据库迁移前自动备份 `steam-stat.bak`。
- `[新增]` 导出 CSV/Excel（会话、好友记录、成就等）。
  - 2026-11-04 落地：「导出与备份」页（`/data-transfer`），Host 侧 `DataExportService` 加 `Features/DataTransfer`。可选 9 个数据集（会话、成就解锁 / 完成度 / 目标、游戏库档案、好友动态、资料变化、Steam 时长快照、截图索引），带时间范围的数据集可以按日期筛选。
    - CSV 为 UTF-8 带 BOM，以 `= + - @` 开头的文本前置单引号防公式注入，时间写本地「yyyy-MM-dd HH:mm:ss」。会话 CSV 的列名与导入器兼容，可以再导入（导入时会去掉防注入的单引号）。
    - xlsx 由手写的最小 OOXML 写入器生成，不引入依赖：每个数据集一个工作表，文本用 inlineStr，时间为带日期格式的序列值，单表超出 1,048,575 行时截断并提示。
    - 先写临时文件再改名，失败或取消不会留下半个文件。
- `[新增]` 导出完整 JSON，用于迁移或二次开发。
  - 2026-11-04 落地：按 SQLite 表原样流式导出（列名同库，时间为 Unix 秒），头部带 `format` / `schemaVersion` / 迁移版本。新表自动包含；`steam_login_token`、`steam_resource_cache`、`global_status`、迁移记录和 `sync_*` 内部表永远不导出。
- `[新增]` 一键手动备份和恢复。
  - 2026-11-04 落地：「导出与备份」页的「备份与恢复」卡片，Host 侧 `BackupService` + 启动时的 `PendingRestoreApplier`。
    - 备份包 `.ssbackup` 是一个 zip：manifest（格式版本、迁移版本、来源设备、数据量、每个文件的 SHA-256）、数据库副本（SQLite 在线备份，清空凭证与资源缓存后 VACUUM）、settings.json、渲染层 localStorage 快照、徽章名缓存，可选存档备份库对象。
    - 可以设密码：整个 zip 用 Core 的 `ChunkedEncryption` 加密（PBKDF2-SHA256 60 万次 + 分块 AES-256-GCM，防截断、重排、篡改）。同步会复用这套加密。
    - 恢复：选文件 →（加密时）输入密码 → 校验清单、哈希和迁移版本（更新版本的备份拒绝恢复）→ 解到 `Restore/pending`，下次启动时在打开数据库之前替换。当前数据库先另存为 `Database/backups/pre-restore-*.bak`，失败时回滚。本机的登录凭证和当前设备身份会带进恢复后的数据库。旧版本的备份随后由正常迁移升级。
    - 「立即重启」走 `appRelaunch`：先以当前时间结束进行中的记录。Electron 先启动的发行包会自动重新拉起；开发模式（.NET 先启动）只退出。
    - 渲染层传给 Host 的口令编码为 `s1:` + Base64，因为 Electron.NET 桥会改写形如时间 / 日期 / GUID 的字符串。
- `[新增]` 多设备同步，三种后端都用端到端加密：
  - 自带存储：本地文件夹、WebDAV、S3，开源免费。
  - 官方托管云：付费，是 Open Core 的商业化点。
  - **Steam 凭证永远不参与同步。**
  - 2026-11-04 落地：自带存储的三种后端；托管云在界面上置灰为「即将推出」，代码里只预留 `ISyncStorage` 接口。「多设备同步」页（`/data-sync`），Core `SteamStat.Core.Sync`（存储、保险库、加密段）+ Host `Features/Sync`（触发器与合并引擎）+ `SyncService`。
    - 同步范围：会话（含备注 / 标签，只同步已结束的）、成就解锁 / 完成度 / 目标清单、游戏库入库时间与档案信息、资料变化、Steam 时长快照，以及设备名和应用名称等元数据（不碰安装状态）。好友记录、截图索引、存档备份、界面偏好不同步。
    - 远端布局：`vault.json`（用口令包裹的随机主密钥，PBKDF2-SHA256 60 万次）+ `devices/{设备}/seg-{序号}.ssec`（JSON → gzip → 分块 AES-256-GCM）+ `devices/{设备}/info.ssec`。每台设备只写自己的目录，后端只需要「列出 / 读 / 写 / 删」，不需要锁。
    - 后端：本地文件夹（先写临时文件再改名）、WebDAV（Depth: 1 逐层 PROPFIND，兼容坚果云）、S3 兼容（手写 SigV4，用 AWS 文档中的签名示例做测试，支持路径风格与虚拟主机风格）。走用户配置的代理，使用独立的 `Sync` HttpClient。
    - 变更捕获：SQLite 触发器在已连接时把变更写进 `sync_outbox`。触发器在启动时幂等安装（不放进 EF 迁移），同时补齐缺失的 `sync_uid`。会话与资料变化按 `sync_uid` 合并，其余表按自然键（`json_array(...)`）合并。
    - 合并：一次同步先拉取、再推送。按行版本（毫秒时间戳 + 设备 ID）最后写入胜出，本机尚未上传的较新修改不会被覆盖。删除保留为墓碑。应用远端变更时置 `applying`，不会回写 outbox。资料变化在 ±1 天内的相同变化视为同一条。
    - 首次连接（或恢复备份后）先拉取远端，再上传全量快照。本机段超过 200 个时写一份快照并删除旧段，新设备只读快照即可。
    - 主密钥与服务器密码经 DPAPI / libsecret 保护后存在 `{UserData}/Sync/config.json`（不进入手动备份）；没有密钥环时只保存在内存中。可以修改口令（用新口令重新包裹同一把主密钥）。
- `[新增]` Public Data 公共数据层：用 GitHub 加 CDN 分发成就 schema 和游戏元数据（类型、标签、开发商），减少请求次数，国内也能访问，为按类型汇总时长提供数据。
  - 2026-11-04 落地：独立公开仓库 `DYH1319/steam-stat-public-data`（生成器 + GitHub Actions），客户端为 Host `PublicDataService` + Core `SteamStat.Core.PublicData`。
    - 数据在 `data` 孤儿分支（每次构建强制推送，只保留最新一代）：`manifest.json` + `apps/{xx}.{sha16}.json` + `achievements/{xx}.{sha16}.json`，xx = appId % 256。分片名带内容哈希，清单带 SHA-256 与大小。
    - 生成器每 6 小时增量抓取约 400 个游戏：先 `seed.json`，再 SteamSpy 热门列表，最后刷新超过 30 天的记录。商店 appdetails 提供类型（english / schinese 名称）、开发商、发行商、发行日期，SteamSpy 提供标签。仓库 Secret `STEAM_WEB_API_KEY` 存在时再抓 GetSchemaForGame（english / schinese）。
    - 客户端每 24 小时刷新一次（GitHub Raw / jsDelivr，国内优化时优先 jsDelivr），只下载本机用到的游戏所在的分片。逐个校验 SHA-256 与大小上限（清单 1 MB、分片 4 MB），CDN 返回较旧的清单时继续用本地较新的。可以在「网络诊断」页关闭。
    - 用途：统计页按游戏类型 / 标签汇总时长（CM 缺开发商、发行商时也用它补充）；CM 不可用且没有缓存时，作为成就 schema 的回退（来源记为 `PublicData`、新鲜度为过期，不写入 CM 缓存，图标只接受 Steam CDN 的 https 地址）。

## 建议路线

1. **P1-A 会话与统计加深。** 先补检测的可靠性（心跳补全、睡眠扣除、AFK、前台检测），再做明细编辑和清洗规则、基线导入，然后是新图表、单游戏详情页和报告。
2. **P1-B 实验功能转正。** 稳定 CM 后默认开启，然后做成就时间线和完成度、好友档案、一起游玩、对比、游戏库档案视角。
3. **P2 门面体验：** 仪表盘、全局时间线、托盘、通知、命令面板、首次引导。
4. **P3 数据可迁移：** 导出、手动备份、公共数据层、自带存储同步，最后才是托管云。
5. **P4 档案扩展：** 截图、资料变化、存档备份，然后是插件化解析。

## 需要提前注意的几个问题

- **范围很大。** 单人维护做不完全部，严格按 P 级推进，每个阶段都保证可以发版。
- **永久保留但没有自动备份，这有矛盾。** 档案馆最大的风险是数据库损坏或硬盘故障。建议至少在 P1 阶段做「每次启动保留最近 N 份快照」这样的轻量保护。
- **AFK 和前台检测在 Linux 上更难。** Wayland 不允许全局键鼠钩子和读取前台窗口，Linux 版可能要降级（只用 Rich Presence 或进程状态判断）。
- **托管云意味着要运营服务器**，还要承担合规和支付责任，和「单人长期维护」冲突最大。建议等自带存储同步稳定、确实有用户需求后再做。
- **数据库加密会让导出、调试和用户自救更麻烦。** 建议做成可选开关，并说明丢失密钥的后果。
